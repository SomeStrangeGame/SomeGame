# Character package

Read this reference when defining, producing, or handing off a SomeGame
character. Also read the repository's current `CharacterLayeringRules.md` and
`ManualContentChecklist.md`; those files own technical and manual acceptance
requirements.

## Required inputs

- approved story brief and scene matrix, or an explicitly scoped existing-story
  character request;
- character narrative function, relationships, emotional arc, and used scenes;
- exact story-project path and stable runtime selector for production work;
- story art direction and approval mode;
- supplied factual evidence and reconstruction boundaries when applicable.

If project, selector, or scene use is not known yet, the skill may produce a
reviewable design brief but must not claim a production-ready runtime package.

## Character brief

Capture only decisions that stabilize later work:

- identity and role in the story;
- protected visual traits and author representation constraints;
- apparent age and any explicit age/state changes;
- silhouette, proportions, posture, palette, hair, and distinctive features;
- default composition, screen scale, gaze, and canvas assumptions;
- sensitivity, factual, or reconstruction constraints;
- whole-image or layered runtime representation and its narrative reason.

## Appearance inventory

Each row maps to an actual scene and records:

- scene and narrative purpose;
- outfit and outfit condition;
- emotion and pose;
- age or story-state transformation when used;
- side, gaze, props, and composition constraints;
- selector, runtime address, target file, and approval status;
- provenance from the approved identity or outfit master.

Do not infer unused combinations. A fallback may be documented, but it is not a
substitute for a required authored appearance.

## Visual-originality criteria

Apply `Docs/AI/rules/OriginalityReviewProtocol.md`. For a character, compare the
recognizable combination of facial construction, silhouette, proportions,
hair, palette, costume structure, accessories, props and pose language. For a
real person, distinguish factual likeness from the artistic choices of a
particular depiction. The shared protocol exclusively owns iteration count,
risk levels, redesign rules, provenance and fail-closed behavior.

## Acceptance evidence

The handoff distinguishes automated evidence from visual judgment and includes:

- neutral identity master and one neutral reference for every used outfit;
- full-body and face contact sheets;
- light- and dark-background alpha proofs;
- exact selector-to-file audit and fallback result;
- visual-originality sources, iteration log, limitations, and final gate result;
- identity, anatomy, scale, gaze, foot-position, edge, and seam review;
- in-game evidence when required;
- rejected drafts, unresolved decisions, and blocking missing variants.
